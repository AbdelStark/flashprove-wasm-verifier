# host

The [independent Wasmtime adapter](wasmtime/README.md) implements the restricted I/O contract for M1 fixtures.

The TypeScript namespace snapshots caller-owned bytes and the complete guest argument vector synchronously. It derives read-only directories from canonical file paths. The Preview 1 adapter gives each instance its own bounded descriptor table, offsets and captured streams. `make test` type-checks the host on Node 24 and checks the audited imports, path and descriptor behavior, and mutation after admission.

The CLI acquisition adapter admits explicit file operands and the allowed configuration and public-key descendants on first guest access. It anchors files and directories on Linux x64 and arm64 with procfs. `make scoped-disk-test` checks native read order with the pinned guest and oracle on x86_64 Linux. [Disk capability decision](../docs/adr/0007-cli-disk-capabilities.md)

The Node runner starts a fresh WebAssembly instance for the parent and each serial child. It checks ordered argument, file and descriptor observations before entering a child branch, then delivers pipe bytes and wait words to the upstream parent. `make replay-test` exercises the transport and compares all published whole calls against the pinned native verifier on x86_64 Linux.

The Node supervisor runs the guest in a fresh worker and owns the 600-second deadline on the calling thread. It checks the versioned reply and waits for clean worker exit before releasing a completed result. A timeout or delivery failure discards any proposed result. After a timeout the admission slot stays held until the worker stops. [Node worker event order](https://nodejs.org/docs/latest-v24.x/api/worker_threads.html#event-message-1)

Pass a `diagnostics` callback in the supervisor options to receive bounded provenance, timing, lifecycle and failure records. The callback receives records after the terminal decision. Guest output remains available through the original byte streams. [Diagnostics schema](../docs/spec/05-observability.md#runtime-diagnostics)

Run `make cli` to build the local `./bin/fpv` command. `make replay-test` invokes that executable against the pinned native oracle. `make scoped-disk-test` checks byte delivery, broken pipes and module integrity. [CLI contract](../docs/spec/02-public-api.md#cli)

`verify(files, args)` in `host/verify.ts` is the Node library entry (R-API-2). It copies the map and arguments before its first await, moves the copies to a fresh worker and leaves the caller's buffers attached. Paths are canonical absolute virtual paths; relative arguments resolve from `/`. The promise always resolves to a `VerifyResult` with both raw streams, LF-split text lines, the verdict that the exit code and last line agree on, and a lossless `result-v1` record. `host/result.ts` decodes that record only from the four closing lines of a whole call at exit 0 or 14, with the pinned field order and forms, the request range and the verdict in agreement. A whole call that claims exit 0 or 14 without such a record latches `host-internal` before anything is published. `make test` checks the decoder and a strict consumer compiled against the emitted declarations. `make verify-test` compares `verify()` with native on published calls. [Result schema](../docs/spec/03-data-model.md#call-result)

`checkAcceptance(result, expected)` (R-API-3, `host/acceptance.ts`) evaluates the eight points of upstream's [When to accept](https://github.com/anthropics/FlashProve/blob/9e2bdd8ff5bf9c62f18263d7dac189b0400b260c/docs/verifying.md#when-to-accept) in that order: verifier, files, id, verdict, coverage, work, commitment, completion. It reads only private evidence that `verify()` binds to the exact result object: the module hash, call mode, the `-id` and `-bits` arguments, copies of the consumed request and token bytes, the closing lines and the record. Changing the returned arrays cannot change a decision. An assembled, copied or cloned result has no evidence and fails all eight rules. Each rule passes only on positive evidence, and failures come back in table order. The request and token are compared byte for byte with the caller's copies, which implies SHA-256 equality, and must name the expected r, e and T. A path operand that does not name a captured file exactly leaves `files` unproved. Ill-typed expectations throw `TypeError`. `make acceptance-test` varies each fact alone on the exact-match and clipped-gap examples. Unit tests cover y-only calls with synthetic evidence, because no pinned example has r = T - 1. [Acceptance RFC](../docs/rfcs/RFC-0008-caller-acceptance.md)

`createVerifier({ moduleUrl, moduleSha256, workerUrl? })` in `host/browser.ts` is the browser entry. It fetches the module and compares its SHA-256 (WebCrypto) with the caller's trusted value before compiling. Other bytes end in `integrity` and are never compiled. `verify()` then admits the call exactly as in Node (`host/call.ts`) and runs it in a fresh dedicated module worker (`host/browser-worker.ts`), which uses the same replay core with a synchronous SHA-256 (`host/sha256.ts`). `BrowserSupervisor` owns the deadline on the calling thread. It checks the schema, request ID and terminal consistency of the reply, settles once, terminates the worker and drops later messages. An `error` or `messageerror` event or an invalid reply ends in `worker`, and a passed deadline ends in `timeout`. Acceptance evidence is derived on the calling thread, never taken from the worker. The worker request carries the compiled module beside the RFC-0007 fields. `make browser-test` runs both published accepted proofs in Chromium with Playwright, checks acceptance, measures main-thread timer gaps during the call, and checks changed module bytes, a terminated worker and a stale request ID. [Worker protocol](../docs/rfcs/RFC-0007-public-interfaces.md#proposed-design)

`make package` stages `build/package` and packs `build/flashprove-wasm-verifier-<version>.tgz`: `bin/fpv`, every compiled host module with its declarations, the audited module and its checksums, the repository LICENSE and NOTICE, FlashProve's NOTICE, LICENSE, THIRD_PARTY.md and licenses/ from the pinned checkout, and the wasi-libc notices in `port/notices`. Export conditions pick the runtime statically: `browser` resolves to `host/browser.js`, everything else to `host/verify.js`, with `./node`, `./browser`, `./worker` and `./cp_verify.wasm` as explicit subpaths. The script refuses an archive that holds any file equal to a published example file, or one that lacks a required notice, and writes `build/package-inventory.json` with each file's size and SHA-256 and the demo bundle's inventory. `make package-test` installs the archive offline in a clean project, compiles a strict consumer through the package exports, runs the installed `fpv`, and verifies `examples/accepted-proof` through the installed package in Node, Deno and Bun. CI pins Deno 2.9.6 and Bun 1.4.4 and requires both. [Release artifacts](../docs/spec/09-release-and-versioning.md#release-artifacts)
